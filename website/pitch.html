胖鱼 PEtFiSh — 产品介绍

v0.6.2 · 2026-05

伙伴不是工具。工具被调用，伙伴始终在场。
从/initproject那一刻起，胖鱼参与你的每一轮交互——感知、守护、维持标准。

问题不在Skill，在协作方式

你用AI写代码。AI很能干。但你注意到几个问题：

  • 它没有边界感——话题漂移了它不知道，上下文污染了它不管，你得自己记住"现在在做什么"。
  • 它不会主动补位——你开始搞部署，它不会说"你还没装部署能力包"。你缺什么得你自己发现。
  • 它容易顺着你说——你提出一个有问题的方案，它说"好的，这是个很好的方向"。没人拦你。
  • 它没有质量底线——推荐的Skill有没有安全问题？触发准确率多少？不知道，也不检查。

这些不是"Skill管理"问题。这是协作质量问题。你需要的不是更多工具，是一个靠谱的伙伴。

四个承诺

常伴 — 每一轮交互都在

Companion Gateway在每条消息前自动执行两步检查：

  1. 话题检测：当前消息和活跃话题什么关系？漂移了吗？风险多高？需要提示吗？
  2. 能力感知：你正在做的事，需要什么能力？你有吗？没有的话要不要装？

然后才进入正常处理。你感觉不到它在，但它每一轮都在。

守护 — 在你掉坑之前拦住

三层感知模型：

  • Tier 1：关键词白名单匹配已知领域（部署→deploy、课程→course、PPT→ppt...）
  • Tier 2：意图级缺口检测——需要外部集成（邮件服务、图表工具、监控）且agent原生能力不覆盖时触发
  • Tier 3：无缺口，静默通过。不打扰。

每个领域每次会话最多提醒一次。上下文守护同理：Fish-trail话题治理器持续监测话题关系和污染风险，高于阈值才出声。

可信 — 信任是验证出来的

胖鱼推荐的每个Skill都经过完整门禁：

Lint (100分制, 40+规则)
  → Score ≥ 80? Continue
Security Audit (0.0-1.0风险分)
  → Risk ≤ 0.5? No CRITICAL? Continue
四条红线检测
  → subprocess+network combo? deny.
  → 敏感路径读写? deny.
  → sudo without approval? deny.
  → subprocess+os combo? deny.
Quality Gate → PASS / CONDITIONAL / FAIL

TrustSkills治理引擎：6维风险（shell/network/file_write/sensitive_data/script_risk/persistence）、5级动作（allow → deny）、4条红线硬拒绝。命中红线不走分数阈值，直接deny。

秉正 — 标准不因便利而降格

反迎合校准机制：

  • 先中性化问题，再给结论——不顺着用户预设表态
  • 先给评分维度，再做判断——至少补一个反方或替代方案
  • 结论与置信度分开表达——证据不足时明确降级
  • 可叠加到任何评审类Skill：outline-design + calibrate、code-review + calibrate

质量门禁同理：不会因为"这个Skill看起来有用"就放水。80分以下不过，0.5以上不过，红线不商量。

为什么是伙伴，不是工具

工具是你想起来才用的。伙伴是一直在的。

  • 工具等你调用——胖鱼每一轮都自动执行Gateway检查
  • 工具不管上下文——胖鱼追踪话题关系，防止污染累积
  • 工具不会说"不"——胖鱼在红线面前硬拒绝，在评审中不迎合
  • 工具用完就走——胖鱼从init到交付全程在场，跨会话保持记忆

Skill管理是手段。让你的AI始终处于正确的工作状态，才是目的。

安装

# macOS / Linux / WSL
curl -fsSL https://raw.githubusercontent.com/kylecui/petfish.ai/master/remote-install.sh \
  | bash -s -- --pack init,companion --detect

# Windows PowerShell
& ([scriptblock]::Create((irm https://raw.githubusercontent.com/kylecui/petfish.ai/master/remote-install.ps1))) -Pack "init,companion" -Detect

装完输入 /initproject。胖鱼询问项目类型，自动装上匹配的能力包。从此刻起，伙伴已就位。
