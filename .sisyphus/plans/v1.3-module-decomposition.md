## 1. Context & Motivation

PEtFiSh has grown from a skill installer to an AI companion platform. Current architecture shows signs of over-consolidation:

- **Companion pack** (`petfish-companion-skill`) bundles 10 skills, 2 MCP servers, 1 command — serving 3 distinct user personas
- **Naming inconsistency**: only 4/96 skills use branded prefixes (fish-*, petfish-*), rest use arbitrary conventions
- **Existing fish-* plan** (`dev_reference/fish-trail_design_and_naming_update/fish_naming_system.md`, 874 lines) was partially implemented (Phase 1 done, Phases 2-3 deferred since v0.5)
- **petfish-market repo** (`kylecui/petfish-market`) exists with functional CI pipeline but zero community content

### 2.2 catalog_query.py Function Inventory

The script serves as a **package registry query layer** (user's opkg analogy):

| CLI Flag | Function | Serves |
|----------|----------|--------|
| `--list` | `list_packs()` | List ALL packs (installed + available) |
| `--search TERM` | `search_packs()` | Search packs by keyword |
| `--profile NAME` | `show_profile()` | Show packs for a profile |
| `--upgrade` | `show_upgrade_command()` | Show upgrade command |
| `--check-failures TEXT` | `check_failures()` | Failure signal detection |
| `--uninstall ALIAS` | `show_uninstall_command()` | Uninstall command |
| `subcommand catalog` | `build_catalog()` | Full catalog builder |
| `subcommand suggest` | `suggest_packs()` | Suggest packs for project |
| `subcommand triggers` | `show_triggers()` | List trigger keywords |
| `subcommand counts` | `show_counts()` | Pack statistics |

**Key insight**: This is NOT "companion sensing" vs "marketplace queries" — it's a **unified registry query interface** that answers both "what do I have?" and "what's available?". Like `opkg list-installed` + `opkg find`. **Do not split.**

## 3. Proposed Architecture

### 3.1 Three Scenarios (User Direction Pending)

#### Scenario A: Full Decomposition (3-pack split)

```
companion pack  → fish-brain (感知+路由+registry查询)
market pack     → fish-market (外部搜索+社区registry)  [NEW PACK]
toolchain pack  → fish-toolchain (skill生命周期8个skill) [NEW PACK]
fish-trail      → unchanged
```

**P0**: fish-brain + fish-market + fish-trail
**Optional**: fish-toolchain

**Pros**: Clean separation of concerns, different update cadences, users can skip toolchain.
**Cons**: 3 packs to install instead of 1, catalog_query.py ownership ambiguous (lives in fish-brain but serves registry queries).

#### Scenario B: Minimum Decomposition (1-pack split)

```
companion pack  → fish-brain (感知+路由+registry查询+外部搜索, 2 skills + catalog_query.py)
toolchain pack  → fish-toolchain (skill生命周期8个skill) [NEW PACK]
fish-trail      → unchanged
```

**P0**: fish-brain + fish-trail
**Optional**: fish-toolchain

**Pros**: Minimal disruption, catalog_query.py stays in one place, only toolchain (clearly different user persona) splits out.
**Cons**: marketplace-connector still bundled with companion.

#### Scenario C: Deferred Decomposition (naming-only)

```
No pack structure changes.
Only rename companion skills to fish-* (10 renames).
```

**Pros**: Zero architectural risk, immediate brand consistency.
**Cons**: Doesn't address the over-consolidation problem.

### 3.2 My Recommendation: Scenario B (Minimum Decomposition)

**Rationale**:

1. **Toolchain has the clearest split signal**: 8 skills serving developers, not end users. Different user persona, different update cadence.
2. **Marketplace-connector + catalog_query.py belong together**: They form the "registry query layer" (user's opkg analogy). Splitting them between packs creates artificial coupling.
3. **petfish-market repo handles community**: External community submissions go through `kylecui/petfish-market` CI. The internal `marketplace-connector` skill is the consumer of that data. They're different layers.
4. **Fish-trail stays unchanged**: Zero coupling already confirmed.

### 3.4 fish-* Naming Scope

| Tier | Skills | Action | Rationale |
|------|--------|--------|-----------|
| **Tier 1: Core** | 10 companion skills | Rename to fish-* | Brand face, user-facing daily |
| **Tier 2: Single-skill packs** | project-initializer → fish-init, anti-sycophancy-calibration → fish-calibrate, petfish-style-rewriter → fish-style, skill-trust-governance → fish-guard | Rename to fish-* | Low rename cost, high brand value |
| **Tier 3: Domain packs** | 54 research, 15 course, 7 deploy, 2 ppt, 2 testdocs | **Keep current names** | 76 skills × rename cost; domain prefixes (research-, course-) already carry clear semantics; fish-research-brief-framer is worse than research-brief-framer |
