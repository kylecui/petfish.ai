## 0. Problem Statement

PEtFiSh currently distributes ALL 13 packs (96 skills) from a single monorepo (petfish.ai). Installers download the entire repo tarball just to pick 1-2 packs. The existing petfish-market repo has only 1 test skill and broken CI.

**User's vision**:
- petfish-market is the **single distribution hub** for all optional skills — both official and community
- All optional skills must be **published to the market** following the same process as community contributors
- Install scripts, `/petfish install`, `/initproject`, `/petfish search` all resolve optional packs via petfish-market
- petfish.ai retains only 4 core packs (12 skills); source code for optional packs stays in petfish.ai for development but is **published to market** for distribution
- petfish-market and petfish.ai must be **kept in sync** — release without market update = broken install

**Key constraint**: "开发在哪" and "从哪安装" are decoupled. Optional pack source code stays in petfish.ai `packs/` for development/testing. Distribution goes through petfish-market's index.json.

### 0.1 Design Principles (from marketplace research)

Based on research of npm, PyPI, Homebrew, Smithery, Glama, and Claude Skills:

| Principle | Source | Application |
|-----------|--------|-------------|
| **Core vs Community explicit separation** | Homebrew (core vs taps) | `@petfish/<pack>` = official (auto-trusted); `@author/<skill>` = community |
| **Scoped namespace** | npm (`@org/name`) | Prevents name conflicts; binds to verified identity |
| **Immutable versions** | npm + PyPI | Published version cannot be overwritten; must bump version |
| **Build → Upload separation** | PyPI (build → twine) | gate (build/validate) → publish (upload to market) |
| **CLI-first publish** | Smithery + npm | `/petfish publish` command |
| **Quality score visible** | Glama | gate_result shown in index.json |
| **Explicit trust for third-party** | Homebrew (`brew tap`) | Deferred to v1.5 (community auto-visible in v1.4) |

**Explicitly NOT adopted**: API server (static JSON + GitHub CI is sufficient), tarball publishing (we reference repo paths), dependency resolution (skills have no transitive deps), dist-tags (v1.4 uses `latest` only, schema reserves for future).

### 0.2 Directory Structure: Core vs Optional Separation

**petfish.ai `packs/` is split into two subdirectories:**

```
petfish.ai/
├── packs/
│   ├── core/                              # 4 core packs — NEVER published to market
│   │   ├── petfish-companion-skill/       #   2 skills + 2 MCPs + 1 cmd
│   │   ├── petfish-toolchain-skill/       #   8 skills
│   │   ├── project-initializer-skill/     #   1 skill + 1 cmd
│   │   └── fish-trail/                    #   1 skill + 1 MCP
│   │
│   └── optional/                          # 9 optional packs — published to market
│       ├── research-skill-pack/           #   54 skills
│       ├── opencode-course-skills-pack/   #   15 skills
│       ├── repo-deploy-ops-skill-pack/    #   7 skills
│       ├── opencode-ppt-skills/           #   2 skills
│       ├── opencode-skill-pack-testcases-usage-docs/  # 2 skills
│       ├── petfish-style-skill/           #   1 skill
│       ├── anti-sycophancy-calibration-pack/  # 1 skill
│       ├── trustskills-governance-pack/   #   1 skill
│       └── fish-reflection-pack/          #   1 skill
```

**Why subdirectories instead of flat**: `skill-publish --all` only scans `packs/optional/`. Zero risk of accidentally publishing core packs. Local installers scan both `core/` and `optional/` subdirectories.

**Installers adaptation**: `PACKS_DIR` resolution scans `$PACKS_DIR/core/` + `$PACKS_DIR/optional/` (local installers). Remote installers download core from petfish.ai, optional from market.

## 1. Architecture

### 1.1 Pack Classification

| Category | Packs | Skills | Source Code | Distribution |
|----------|-------|--------|-------------|-------------|
| **Core** | companion, toolchain, init, context | 12 | petfish.ai `packs/core/` | Direct from petfish.ai release |
| **Optional** | research, course, deploy, ppt, testdocs, petfish, calibrate, trust, reflect | 84 | petfish.ai `packs/optional/` | Published to petfish-market, installed via market index.json |

**Why toolchain is core**: quality-gate is used by petfish-market's own CI. Moving it creates a circular dependency.

### 1.2 Install Flow (After v1.4)

```
/petfish install course
  ↓
fish-brain (catalog_query.py):
  1. Is "course" a core alias? → No
  2. Query petfish-market/index.json → found: pack entry
  3. Return install command with market-sourced download
  ↓
Remote installer:
  1. Download from petfish-market repo → get pack info (repo=kylecui/petfish.ai, ref=vX.Y.Z, path=packs/optional/opencode-course-skills-pack)
  2. Extract, copy skills/agents/commands to target
  3. Update installed-packs.json
```

```
/petfish install companion
  ↓
fish-brain:
  1. Is "companion" a core alias? → Yes
  2. Return standard remote-install command (from petfish.ai)
```

### 1.3 Publish Flow

```
Developer finishes optional pack changes in petfish.ai
  ↓
1. Run quality-gate locally → PASS
2. Run skill-publish → generates registry JSON for changed packs
3. Commit registry JSON to petfish-market (manual PR or CI)
4. petfish-market CI validates + rebuilds index.json
5. Users can now install updated version via /petfish install
```

Community contributors follow the same steps (2-4) via PR to petfish-market.

### 1.4 Sync Maintenance Rules

On every petfish.ai release:
1. [MANDATORY] **Before tagging**: Run `skill-publish --all --ref vX.Y.Z` → commit to petfish-market → verify CI passes
2. [MANDATORY] **Before tagging**: Verify petfish-market index.json contains all 9 optional packs with correct ref
3. [MANDATORY] **Before tagging**: Verify petfish-market CI passes (gate toolchain path valid)
4. [MANDATORY] **After tagging**: Test: `/petfish install <each-optional-alias>` succeeds from clean environment
5. Update REPO-LANDSCAPE.md §5 known issues if any found

**Release sequence**: dev → PR → merge to dev → skill-publish → market CI → merge to master → tag → verify

## 2. New Skill: skill-publish

### 2.1 Purpose

Bridge the gap between quality-gate (PASS) and actual marketplace availability.

### 2.2 What It Does

1. Reads pack-manifest.json for specified pack(s)
2. Generates registry JSON entry(s) in petfish-market schema format
3. Validates entries against petfish-market CONTRIBUTING.md schema
4. Outputs files ready for commit to petfish-market

### 2.3 Script

`packs/core/petfish-toolchain-skill/.opencode/skills/skill-publish/scripts/publish_pack.py`

```
Usage:
  uv run publish_pack.py --pack research-skill-pack --ref v1.4.0 --output ../petfish-market/registry/official/
  uv run publish_pack.py --all --ref v1.4.0 --output ../petfish-market/registry/official/
  uv run publish_pack.py --pack research-skill-pack --dry-run  # preview without writing
```

### 2.4 Generated Output

Per-pack registry entry in `registry/official/<pack-name>.json`:
```json
{
  "namespace": "official",
  "name": "opencode-course-skills-pack",
  "alias": ["course"],
  "description": "Course development lifecycle / 课程开发全生命周期",
  "repo": "kylecui/petfish.ai",
  "ref": "v1.4.0",
  "path": "packs/optional/opencode-course-skills-pack",
  "skill_count": 15,
  "license": "Apache-2.0",
  "author": "petfish-team",
  "gate_result": { ... }
}
```

Per-skill entries auto-generated from pack's skill list (for granular search).

## 4. Risks

| Risk | Severity | Mitigation |
|------|----------|------------|
| Market index.json stale after release | High | skill-publish + documented sync step in release checklist |
| Dual-repo coordination overhead | Medium | REPO-LANDSCAPE.md sync rules + release checklist |
| Network dependency on two repos | Medium | Fallback: market → petfish.ai tarball → local |
| skill-publish generates incorrect registry entries | Medium | `--dry-run` mode + schema validation in rebuild_index.py |
| Backward compat break for existing users | High | Installers try market first, fallback to ALL_PACKS tarball |
| petfish-market CI still broken after Phase 1 | Low | Phase 1 step 1.1 explicitly fixes it |

### In Scope (v1.4)

- skill-publish new tool

- L5 Phase A (batch description upgrade) — orthogonal to market work
