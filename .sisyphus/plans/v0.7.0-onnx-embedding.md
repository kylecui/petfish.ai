## 1. Problem Statement

Current topic_detect uses bilingual keyword Jaccard with synonym groups (v0.6.10). This achieves 89-100% accuracy on test cases but fundamentally cannot detect:
- Semantic relationships not expressible as keyword overlap
- Product-specific names not in the bilingual map or synonym groups
- Nuanced domain boundaries (e.g., "refactoring auth logic" vs "writing auth documentation")

The keyword approach requires ongoing maintenance of bilingual_map and synonym_groups for every new domain.

## 2. Solution: Tier 2 Embedding Similarity

Add ONNX-based sentence embedding as a **Tier 2 fallback** within `_check_semantic_drift()`:

```
Tier 1: Bilingual keyword Jaccard (free, <1ms)
  → relevance >= 0.10: on-topic → return None (continue)
  → relevance == 0.0 with 3+ keywords: drift → return fork
  → ambiguous zone (0.0 < relevance < 0.10): consult Tier 2

Tier 2: Embedding cosine similarity (118MB model, ~30ms)
  → similarity > 0.5: on-topic → return None (continue)
  → similarity < 0.3: drift → return fork
  → 0.3-0.5: low-confidence fork (risk=35, confidence=0.55)
```

## 3. Model Selection

**Model**: `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`

| Property | Value |
|----------|-------|
| Source | HuggingFace official repo, `/onnx` subfolder |
| Variants | `model_quint8_avx2.onnx` (x86), `model_qint8_arm64.onnx` (ARM64) |
| Size on disk | **118 MB** per variant |
| RAM at runtime | ~250-350 MB peak |
| Embedding dim | 384 |
| Languages | 50+ including Chinese and English |
| Inference latency | ~20-50ms per sentence pair (CPU) |
| Pooling | **NOT included** — must apply mean pooling + L2 normalize manually |

### Why this model
- Best multilingual coverage at smallest quantized size
- No lighter alternative exists for zh+en mixed text
- int8 quantized variants exist for both x86 and ARM64

## 5. Architecture

### New file: `embeddings.py`

Located at: `packs/core/fish-trail/.opencode/skills/fish-trail/mcp/context-state/embeddings.py`

```
EmbeddingManager
├── __init__(base_dir: str)
├── available: bool (property — are deps/platform supported? Does NOT require model present)
├── similarity(text_a: str, text_b: str) -> float | None  (calls _ensure_model internally)
├── _get_session() -> (session, tokenizer) | (None, None)  (lazy: triggers _ensure_model on first call)
├── _load_model() -> (session, tokenizer)
├── _ensure_model() -> str (download or locate model file — called by similarity/get_session)
├── _choose_variant() -> str (platform-specific model filename)
├── _mean_pool(token_embeddings, attention_mask) -> ndarray
├── _normalize(embeddings) -> ndarray
└── _encode(text) -> ndarray (384-dim embedding)
```

### Integration into TopicDetector

```python
# topic_detector.py — modified __init__
def __init__(self, embedding_manager=None):
    self._embedding = embedding_manager
    # ... existing init ...

# topic_detector.py — modified _check_semantic_drift
def _check_semantic_drift(self, keywords, current_topic):
    # ... existing keyword Jaccard logic ...
    
    # Ambiguous zone: consult embedding if available
    if 0.0 < relevance < 0.10 and self._embedding and self._embedding.available:
        topic_text = current_topic.get("title", "") + " " + current_topic.get("scope", "")
        sim = self._embedding.similarity(input_text, topic_text)
        if sim is not None:
            if sim > 0.5:
                return None  # on-topic
            elif sim < 0.3:
                return fork_result(risk=45, confidence=0.65)
            else:
                return fork_result(risk=35, confidence=0.55)
    
    # ... existing fallback logic unchanged ...
```

### Integration into server.py

**Note on `available` property semantics**: `available` returns `True` when the platform and dependencies (onnxruntime, tokenizers, numpy) are importable — it does NOT require the model file to be present. The model is downloaded lazily inside `similarity()` → `_get_session()` → `_ensure_model()`. This means first call to `similarity()` may trigger a download. If download fails, `similarity()` returns `None` and the caller falls back to keyword-only.

```python
# server.py — ContextStateServer.__init__
from topic_detector import TopicDetector

# Optional embedding
try:
    from embeddings import EmbeddingManager
    _HAS_EMBEDDINGS = True
except ImportError:
    _HAS_EMBEDDINGS = False

class ContextStateServer:
    def __init__(self, base_dir):
        embedding_mgr = None
        if _HAS_EMBEDDINGS:
            embedding_mgr = EmbeddingManager(base_dir)
        self.detector = TopicDetector(embedding_manager=embedding_mgr)
```

## 6. Model Delivery

### Download Strategy: Lazy fetch on first use via `huggingface_hub`

```python
def _ensure_model(self) -> str:
    # 1. Check env override
    if local := os.environ.get("FISH_TRAIL_MODEL_PATH"):
        return local
    
    # 2. Check local cache in base_dir/models/
    local_path = os.path.join(self.base_dir, "models", self._choose_variant())
    if os.path.exists(local_path):
        return local_path
    
    # 3. Download via huggingface_hub (caches in ~/.cache/huggingface/)
    from huggingface_hub import hf_hub_download
    return hf_hub_download(
        repo_id="sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2",
        filename=f"onnx/{self._choose_variant()}",
    )
```

### Tokenizer files
Also download: `tokenizer.json`, `tokenizer_config.json`, `special_tokens_map.json` — all from the same repo root (~3MB total).

### Air-gapped / offline environments
- Set `FISH_TRAIL_MODEL_PATH=/path/to/model.onnx` to skip download
- Or pre-populate `~/.cache/huggingface/` and set `HF_HUB_OFFLINE=1`
- Or place model at `.petfish/fish-trail/models/model_quint8_avx2.onnx`

## 7. Configuration

Add to `{base_dir}/config.json` (where `base_dir` defaults to `.petfish/fish-trail`; JSON format — no YAML dependency needed):

```json
{
  "embedding": {
    "enabled": true,
    "preload": false,
    "timeout_ms": 2000,
    "model_path": "",
    "intra_threads": 2
  }
}
```

Server loads config via `json.load()` (stdlib). If file missing, use defaults above.

Default: `enabled: true, preload: false` — model loads lazily on first drift check that enters the ambiguous zone.

## 8. Performance Budget

| Operation | Time | When |
|-----------|------|------|
| Import onnxruntime | 80-300ms | First embedding call |
| Load model (InferenceSession) | 1-3s | First embedding call |
| Warmup inference | 50-200ms | After model load |
| **Total cold start** | **~2-4s** | **Once per server lifetime** |
| Tokenize + infer + pool | 20-50ms | Each subsequent call |
| Keyword Jaccard (Tier 1) | <1ms | Every topic_detect call |

Since Tier 2 only fires in the ambiguous zone (0.0 < keyword_relevance < 0.10), most calls never touch the embedding model. Expected percentage of calls hitting Tier 2: <15%.

## 9. Fallback & Degradation

The system MUST work identically to v0.6.10 when:
- `onnxruntime` not installed → keyword-only (zero-dep baseline)
- `tokenizers` not installed → keyword-only
- Model file missing / download fails → keyword-only
- macOS Intel (x86) → keyword-only (ORT doesn't support)
- Python < 3.11 → keyword-only (ORT requires 3.11+)
- Inference timeout exceeded → keyword-only for that call
- Any exception during embedding → log warning, keyword-only

No user-facing behavior change unless embedding is explicitly enabled AND all deps are present.

## 11. Risks & Mitigations

| Risk | Impact | Mitigation |
|------|--------|------------|
| 118MB model too large for some users | Medium | Fully optional; keyword fallback always available |
| Cold start blocks first MCP call | Low | Lazy load only on ambiguous-zone hit; preload option available |
| onnxruntime breaks on exotic platforms | Low | try/except with full fallback |
| Model download fails (network/firewall) | Medium | Env var override + manual placement + offline mode |
| Memory pressure (350MB peak) | Low | Server is long-running, one instance; configurable disable |
| Embedding gives wrong similarity | Medium | Only used in ambiguous zone; keyword result takes priority for clear cases |
| Breaking zero-dep policy for existing users | High | **Strictly optional** — no change to base behavior |

## 12. What This Does NOT Do

- Does NOT replace keyword Jaccard — it supplements it in the ambiguous zone only
- Does NOT require GPU — CPU-only, always
- Does NOT bundle the model — download on first use
- Does NOT add mandatory dependencies — all optional with graceful fallback
- Does NOT change the topic_detect API — same input/output contract
- Does NOT affect server startup time by default (preload: false)
