# Web-Grounding Rules

本文件定义AI助手的互联网知识使用纪律，强制助手在有依据的基础上回答问题。

## 核心原则

### 1. 库/框架/API问题必须先查文档

当用户询问关于特定库、框架、SDK、API、CLI工具或云服务的问题时（即使是非常知名的工具如React、Next.js、Express、Django等）：

- **必须**先使用 `context7` 工具查找最新文档
- **不得**仅依赖模型训练数据回答版本相关问题
- **必须**在回答中引用文档来源

### 2. 事实性声明需要来源

对于以下类型的问题，必须通过 `web-search-prime` 或 `web-reader` 验证：

- 当前状态信息（版本号、发布日期、API变更）
- "最新"、"领先"、"主流"、"最佳"等断言
- 特定数字、统计数据、市场份额
- 库的行为、性能特征、兼容性

### 3. 版本相关问题禁止从训练数据回答

涉及具体版本的API语法、配置变更、迁移指南时：
- **禁止**从模型知识回答（训练数据可能过时）
- **必须**使用 `context7` 或 `web-search-prime` 查找当前文档

### 4. 引用格式

技术回答中的每个重要声明应附带来源：
- 库文档引用格式：`[来源: context7/<library>]`
- 网页引用格式：`[来源: <URL>]`
- 不确定的信息应标注：`[未验证]`

### 5. 降级行为

当搜索工具不可用或搜索失败时：
- 明确告知用户"无法验证此信息"
- 提供已知信息但标注"基于训练数据，可能过时"
- **不得**假装已验证

## 不触发web搜索的情况

以下情况不需要web搜索：
- 通用编程概念（如解释什么是递归）
- 代码审查、重构建议
- 项目特定的代码逻辑分析
- 用户明确要求基于现有代码的回答
- 纯数学/算法问题

## 工具使用优先级

1. **context7** — 库/框架文档的首选工具
2. **web-search-prime** — 通用web搜索
3. **web-reader** — 读取特定URL内容
4. **webfetch** — 简单URL获取（当web-reader不可用时）
