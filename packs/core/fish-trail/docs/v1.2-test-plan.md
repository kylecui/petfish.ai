# Fish Trail v1.2 Test Plan & Evaluation Methodology

## 1. Overview

v1.2 adds two memory compression features on top of the v1.1 3-block cache-stable architecture:

| Feature | Description | Feature Flag | Phase |
|---|---|---|---|
| **Semantic Reflective Brief** | Agent writes a compressed brief at topic_update time; MCP server validates quality; heuristic fallback for invalid/missing briefs | `reflectiveBriefEnabled` | Alpha (P7) |
| **Adaptive Compression** | Reads mcp-call-log.jsonl to measure topic_show recall signal; state machine auto-switches between compact and full Focus block format | `adaptiveCompressionEnabled` | Beta (P8) |

Both features are fully gated behind flags defaulting to `false`. When both flags are `false`, behavior is byte-identical to v1.1.

## 3. Feature 1: Semantic Reflective Brief

### 3.1 Architecture

```
Agent works → interaction ends → topic_update(summary="...", reflective_brief="...")
                                                          ↓
                                                   MCP Server
                                                   ├── Layer 1: _validate_brief()
                                                   │   ├── 10 ≤ length ≤ 200
                                                   │   ├── has word characters
                                                   │   └── no low-quality patterns
                                                   ├── Layer 2: _heuristic_brief() (fallback)
                                                   │   ├── Strategy 1: At:/Progress:/Status: prefix
                                                   │   ├── Strategy 2: First sentence
                                                   │   └── Strategy 3: Hard truncate
                                                   └── Layer 3: Auto-degradation
                                                       └── rejected/attempts > 0.5 && attempts ≥ 3
                                                         
Plugin reads reflective_brief → injects in Focus block
  ├── reflectiveBriefEnabled=true + field exists → use it
  └── otherwise → fallback to reflectiveBrief() heuristic
```

### 3.3 Manual Integration Tests

These require running OpenCode with `reflectiveBriefEnabled=true` and interacting with the agent.

#### IT-BRIEF-01: Agent writes valid brief at topic_update

**Steps**:
1. Create a topic: `topic_create(title="test-brief", scope="Testing reflective brief")`
2. Have a multi-turn interaction about a specific task (e.g., "fix the type error in auth.ts")
3. At end of interaction, observe agent calls `topic_update` with `reflective_brief`
4. Read topic file from `.petfish/fish-trail/topics/<id>.json`

**Expected**:
- Topic JSON contains `reflective_brief` field
- `brief_model` = `"agent"`
- `reflective_brief` length between 10-200 characters
- `reflective_brief` contains concrete action/decision, not "继续开发中"
- `brief_stats.agent_attempts` incremented
- `brief_stats.agent_accepted` incremented

**Verify**:
```bash
cat .petfish/fish-trail/topics/<topic-id>.json | python -m json.tool
```

#### IT-BRIEF-02: Heuristic fallback when no brief provided

**Steps**:
1. Create a topic with a summary but **do not** include `reflective_brief` in topic_update
2. Call `topic_update(topic_id="...", summary="Implementing the new feature. Progress: 60% done. Still need to write tests.")`
3. Read topic file

**Expected**:
- Topic JSON contains `reflective_brief` field
- `brief_model` = `"heuristic"`
- Brief content extracted from summary (Strategy 1 or 2)

#### IT-BRIEF-03: Invalid brief triggers rejection

**Steps**:
1. Call `topic_update(topic_id="...", summary="...", reflective_brief="继续")`
2. Read topic file

**Expected**:
- `reflective_brief` field is **NOT** updated (invalid brief is rejected)
- `brief_stats.agent_rejected` incremented
- Previous `reflective_brief` (if any) is preserved

#### IT-BRIEF-04: Auto-degradation after repeated invalid briefs

**Steps**:
1. Call topic_update with invalid brief 3 times: `reflective_brief="ok"`, `reflective_brief="done"`, `reflective_brief="继续"`
2. Read topic file after each call
3. On 4th call, provide NO brief, just update summary

**Expected**:
- After 3 rejects: `brief_stats.degraded` = `true`
- `agent_rejected / agent_attempts > 0.5` and `agent_attempts ≥ 3`
- 4th call: MCP server ignores agent brief, always uses heuristic
- `brief_model` = `"heuristic"`

#### IT-BRIEF-05: Focus block uses reflective_brief

**Steps**:
1. Ensure a topic has a valid `reflective_brief`
2. Start a new turn in OpenCode
3. Observe the injected `## Focus` block in the system prompt

**Expected**:
- Focus block shows the `reflective_brief` content (not the full summary truncated)
- Compare with v1.1: v1.1 would show heuristic-truncated summary; v1.2 should show the agent-written brief

**How to verify**: Check the injected system prompt (enable `debug: true` to see logs on stderr).

#### IT-BRIEF-06: Backward compatibility — no brief

**Steps**:
1. Set `reflectiveBriefEnabled: false`
2. Interact normally
3. Check Focus block

**Expected**:
- Focus block uses `reflectiveBrief()` heuristic (same as v1.1)
- No `reflective_brief` field read from topic JSON
- Behavior byte-identical to v1.1

## 4. Feature 2: Adaptive Compression

### 4.1 Architecture

```
Every injection turn:
  ├── measureRecallSignal(fishTrailDir, 20)
  │   └── Read mcp-call-log.jsonl last 64KB
  │   └── Count topic_show calls / total entries (last 20)
  │   └── Return frequency 0.0~1.0 (or null if no data)
  │
  ├── resolveAdaptiveMode(prevState, signal, roundCounter)
  │   ├── UNKNOWN → compact (signal ≤ 0.1) or full (signal > 0.3)
  │   ├── COMPACT → FULL: signal > 0.3 for 3 consecutive rounds, cooldown passed
  │   ├── FULL → COMPACT: signal ≤ 0.1 for 3 consecutive rounds, cooldown passed
  │   ├── Cooldown: 10 rounds after any switch
  │   └── Oscillation: 5 switches in <50 rounds → lock FULL for 20 rounds
  │
  └── formatActiveFocusBlock()
      └── compact → formatActiveFocusCompact()
      └── full → formatActiveFocusFull()
```

## 5. Performance Evaluation

### 5.1 Signal Measurement Latency

**What to measure**: Time for `measureRecallSignal()` to read and parse `mcp-call-log.jsonl`.

**Method**:
1. Enable `debug: true` in plugin config
2. Run 100 turns
3. Collect stderr logs with timing: `grep "adaptive signal=" stderr.log`
4. Calculate p50, p95, p99

**Thresholds**:

| Metric | Target | Alert Threshold |
|---|---|---|
| p50 | < 1ms | > 2ms |
| p95 | < 3ms | > 5ms |
| p99 | < 5ms | > 10ms |

**If p99 > 10ms**: Check `mcp-call-log.jsonl` file size. Log rotation is at 1MB. If file exceeds 1MB, rotation may have failed.

### 5.2 Plugin Injection Overhead

**What to measure**: Total time added by v1.2 code (metrics computation + signal measurement) vs v1.1 baseline.

**Method**:
1. Run 50 turns with v1.1 config (both flags false) — record baseline
2. Run 50 turns with v1.2 Alpha config (reflectiveBriefEnabled only)
3. Run 50 turns with v1.2 Beta config (both flags true)
4. Compare injection times from debug logs

**Threshold**: v1.2 overhead < 5ms per turn over v1.1 baseline.

### 5.3 Token Cost Impact

**What to measure**: Change in Focus block token count with brief vs without.

**Method**:
1. Enable `reflectiveBriefEnabled: true`
2. After 10+ interactions with briefs written, measure Focus block token count
3. Compare with v1.1 Focus block (heuristic truncated summary)

**Expected**:
- Brief (10-200 chars) vs truncated summary (up to 120 chars) — similar or smaller token count
- Brief quality should be higher (more information-dense) even if token count is similar

### 5.4 Metrics Collection Overhead

**What to measure**: `computeBriefMetrics()` execution time.

**Method**: Metrics are computed every 10 rounds. Check debug logs for timing.

**Threshold**: < 10ms per computation (reads all topic files from disk).

### 6.2 Alpha (P7) Metrics — Reflective Brief

| Metric | Definition | Target | Alert |
|---|---|---|---|
| `brief_hit_rate` | Fraction of topics with a reflective_brief | ≥ 0.7 | < 0.5 |
| `agent_reject_rate` | Fraction of agent-submitted briefs rejected by MCP | ≤ 0.2 | > 0.3 |
| `heuristic_ratio` | Fraction of briefs generated by heuristic (not agent) | < 0.5 | > 0.7 |
| Recall quality | Agent can accurately summarize prior work using injected context | No degradation vs v1.1 | User reports recall loss |

**Data collection**: After each interaction session, check `_brief_metrics`. Record in tracking spreadsheet.

### 6.3 Beta (P8) Metrics — Adaptive Compression

| Metric | Definition | Target | Alert |
|---|---|---|---|
| `mode_switches_total` | Total mode switches in last 100 rounds | < 5 | > 10 |
| `unstable_locks` | Times oscillation detection triggered | 0 | > 0 |
| `signal_p95` | 95th percentile of topic_show frequency | Stable within ±0.05 of initial | Oscillating |
| `cold_starts` | Rounds with null signal | < 10% of rounds | > 30% |

### 6.4 Alert Response Matrix

| Alert | Possible Cause | Action |
|---|---|---|
| `agent_reject_rate > 0.3` | Agent rules not effective; agent not writing quality briefs | Check if AGENTS.md brief section is loaded; review agent behavior |
| `heuristic_ratio > 0.7` | Agent not providing briefs at all | Check if topic_update is being called; verify MCP server logs |
| `brief_hit_rate < 0.5` | Brief system not activating | Check `reflectiveBriefEnabled` flag; check MCP server running |
| `mode_switches_total > 10` | Signal noisy; thresholds need calibration | Review mcp-call-log.jsonl; adjust signal thresholds |
| `unstable_locks > 0` | Signal oscillating wildly | Check if Agent is repeatedly querying topic_show; consider raising cooldown |
| `signal_cold > 30%` | mcp-call-log.jsonl missing or empty | Check MCP server logging is enabled; verify file rotation |

## 9. Rollback Procedures

| Scenario | Config Change | Expected Recovery |
|---|---|---|
| Brief quality bad / recall degraded | Set `reflectiveBriefEnabled: false` | Reverts to v1.1 heuristic truncation immediately |
| Adaptive switching too frequent | Set `adaptiveCompressionEnabled: false` | Locks to compact format (same as v1.1) |
| Both features problematic | Set both flags `false` | Fully reverts to v1.1 behavior |
| `injected-block-state.json` corrupted | Delete the file | Plugin auto-rebuilds on next turn (cold start) |
| Topic JSON `reflective_brief` field corrupted | No action needed | Plugin ignores unparseable brief, falls back to summary |

**Full revert to v1.1**: Switch to branch at commit `3e58529` (last commit before v1.2 changes).
